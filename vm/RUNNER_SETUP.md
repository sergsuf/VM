# Налаштування Self-Hosted Runner для оркестрації ВМ

Цей гайд описує, як підключити твою Windows-ВМ (або хост Hyper-V) до GitHub Actions, щоб оркестратор у чаті міг запускати там `Antigravity CLI`, `max-auto` або PowerShell-команди та забирати логи/скріншоти.

## 1. Створення раннера в GitHub

1. Відкрий репозиторій **sergsuf/VM** на GitHub → **Settings** → **Actions** → **Runners**.
2. Натисни **New self-hosted runner**.
3. Обери **Windows** та архітектуру **x64**.
4. Виконай команди з інструкції GitHub на своїй Windows-ВМ у PowerShell (наприклад, у папці `C:\actions-runner`).

## 2. ВАЖЛИВО для GUI (3ds Max / AutoHotkey / UIA)

> **Не встановлюй раннер як Windows Service**, якщо плануєш запускати `max-auto` або будь-які GUI-дії!
> Windows Service працює в ізольованій **Session 0** і не бачить робочого столу користувача, вікон 3ds Max та не може робити кліки/скріншоти.

Натомість запускай раннер **в інтерактивній сесії залогіненого користувача**:
```powershell
cd C:\actions-runner
.\run.cmd
```
*(За бажання можеш додати `run.cmd` у Планувальник завдань Windows / Task Scheduler з опцією **"Run only when user is logged on"** для автозапуску після старту ВМ).*

## 3. Перевірка Antigravity CLI

Перед першим запуском переконайся, що в тому ж середовищі (де запущений `.\run.cmd`) доступні:
- `antigravity` (або інша назва бінарника CLI, яку ти вкажеш у `cli_executable`) — перевір у PowerShell: `Get-Command antigravity`
- `.venv` у корені репозиторію (якщо використовуєш `max-auto`)

Також перевір, яким прапорцем твій Antigravity CLI приймає промпт у неінтерактивному режимі (за замовчуванням у workflow стоїть `-p`, але це можна змінити параметром `cli_args_prefix`).

## 4. Як це працює в роботі

1. Ти пишеш у чаті оркестратору, що треба зробити на ВМ (наприклад: *"Запусти на ВМ перевірку через CLI..."* або *"Зроби `max-auto run` і перевір чи є нові попапи"*).
2. Оркестратор запускає workflow через `gh workflow run vm-orchestrator.yml ...`.
3. Раннер на ВМ виконує завдання через `vm/run_orchestrator_task.ps1` і завантажує папку `logs/` (разом зі скріншотами `logs/unknown_popups/`) в артефакти.
4. Оркестратор завантажує артефакти через `gh run download`, аналізує логи/скріншоти й звітує тобі про результат.
